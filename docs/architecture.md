# 架构说明

## 总体结构

```text
浏览器
  ├─ index.html + styles.css
  ├─ app.js
  └─ city-hotspots.js
          │ HTTP
          ▼
      server.mjs
       ├─ 静态文件服务
       ├─ /api/amap/places
       └─ /api/deepseek
          │
          ├─ 高德天气与地点接口（可选）
          └─ DeepSeek 文本生成接口（可选）
```

## 浏览器端

`app.js` 负责城市切换、地点筛选、地图标记、详情面板、收藏状态和攻略对话。成都数据由 `city-hotspots.js` 注入窗口对象。没有后端或外部 API 时，页面仍可使用内置数据和本地降级攻略。

## 服务端

`server.mjs` 使用 Node.js 原生 `http` 模块提供静态资源，并把可选的高德和 DeepSeek 请求放在服务端执行。服务端读取本机环境变量，避免将第三方凭证发送到浏览器。请求体有大小限制，聊天消息会做数量和长度截断，错误响应使用面向用户的通用提示。

## 数据流

1. 浏览器从本地静态文件加载页面和热点数据。
2. 用户切换非内置城市时，浏览器请求 `/api/amap/places`。
3. 服务端使用城市名称查询地点数据，并可选调用文本生成服务整理卡片。
4. 用户提交攻略问题时，浏览器请求 `/api/deepseek`。
5. 服务端加入本地地点和可选天气上下文后调用文本生成服务，再把文本返回浏览器。
6. 浏览器对生成文本做转义和轻量 Markdown 排版。

## 边界和扩展

当前实现适合本地产品原型。若要部署到公网，需要补充身份认证、限流、结构化日志、错误监控、依赖锁定、隐私政策、第三方服务条款确认和生产级静态资源配置。扩展功能时应保持城市数据字段、地点卡片结构和 API 返回形状兼容。
